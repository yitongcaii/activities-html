1一句话定位

它到底是个啥
文化活动里最难、最容易踩坑、又最高频的两类交付——「写给人看的高管谈参」和「主持人串词」， 本 skill 把 9 份真实主持稿抽象成一套通用方法论资产库，让你按场合 10 分钟产出一版 干净、有温度、可读的初稿 + 一张把关清单。所有部门 / 公司 / 人名 / 奖项都是占位符，由你填。

3核心方法论（结构化）

它怎么干活的

① 两遍生成引擎（解决"满屏括号 / 没温度"）

第一遍 · 规划（不打印）

  • 套活动骨架、选互动（只 supervisor/exec）
  • 定隐喻意象、设计情绪起伏
  • 只在脑内完成，不出现在成品

第二遍 · 交付

  • 只写干净口语脚本
  • 读者看不到任何规划痕迹
  • 温度靠写法，不靠编数据

4约束 / 避雷清单

这些红线踩了就不合格
不产平级朋友向内容——上下级 / 高管场合绝不用朋友互损型破冰。
不杜撰——你没给的真实信息一律 { } 占位，最多写「比如：xx」提示，绝不编活动名 / 人名 / 奖项。
零元标注——成品禁止出现 (通用模板) (示例) [引用iX] 这类记号。
cue 单行——舞台提示用 【cue: …】 独占一行，不黏在台词前。
隐喻贯穿——开场定一个比喻，全篇同一意象回扣，不中途换。
双向挥手——混合会场异地打招呼用镜头两边互相挥手，绝不写单向「让我们看见你」。
职位 / 保密必确认——领导职位与保密范围（截屏 / 录屏限制）由你跟秘书核对后填。
必过自检闸——交付前逐项确认（通读顺 / 无元标注 / cue 单行 / 关系分层 / 已出 HTML 三色）。
HTML 不带 yitong 页脚——本 skill 生成的网页版一律用中性页脚「颜色仅为阅读辅助标注」，非个人沉淀发布。

6边界与依赖

啥能搞、啥搞不定、要啥环境

依赖 / 模型要求

  • 通用对话大模型即可，无需额外算力
  • 放 ~/.workbuddy/skills/ 重启生效
  • 资产库为 JSON，加载即用

不适用场景

  • 平级朋友向破冰（受众分层硬约束剔除）
  • 涉及编制 / 晋升 / 去留等敏感 QA 的高风险场合（谈参为轻量版，无应答护栏）
  • 对外正式发布稿（需人工复核脱敏与口径）
所有 { } 留空由你填，AI 不替你写真实部门 / 人名 —— 人工所有权不变。
