隔离方案 · Phase 0 必做

5 行

给 server/db/init.js 加环境变量覆盖，测试指向临时库，不碰你真库：

const dataDir = process.env.DATA_DIR
  || path.join(__dirname, '../data');
// 测试启动：
DATA_DIR=/tmp/lottery-test npm run dev
测试前后用 seed 脚本灌白名单 / 奖品。本地 dev 不传 DATA_DIR 时行为完全不变。

用户端 / 用例

  • 首页加载：标题/口号取自 /api/config，盲盒按钮可见
  • 资格-白名单内：输入工号可点
  • 资格-非白名单：灰色提示 not_in_whitelist
  • 抽奖主流程：点拆盲盒→中奖卡片→选领取方式→提交 claimed
  • 已抽提示：返回 already_drawn
  • 库存为 0：该分类文案 / 403
  • 抽奖券用完：ticket_pools 耗尽 → 403 文案
📊

管理端 /admin 用例

  • 鉴权：错密码失败；未登录调受保护接口 401
  • 看板：总/已抽/剩余数字 + 奖品维度表渲染
  • 中奖名单：抽完后列表是否真有数据（⚠ 见风险点）
  • 资格：加人/删人、搜索过滤、Excel 导入、单人/批量重置
  • 奖品：增改删 / 图片上传
  • 领奖：筛选、标记领取、导出 Excel（下载断言）
  • 配置：改文案 → 前端即时反映
🔗

数据一致性回归（API 层）

  • 抽一次：remaining_stock -1，看板同步
  • 重置：库存 +1，users.has_drawn=0
  • 防重复：连抽两次第二发应被拒
抽奖用 Math.random() 选奖，e2e 只能断言「出了某奖品 + 库存 -1」，不能断言具体奖。
⚡

写测试时必暴露的 3 个风险点（高价值）

  • 防重复抽奖实际没生效：lottery.js:116 的 /draw 只收 category，插入 user_id=0，从不置 users.has_drawn=1；而 /check 的 already_drawn 全靠这个字段 → 同一工号可一直抽。README 写的「同工号只能抽一次」后端没兜底。
  • 中奖名单 / 领奖信息 / 导出可能恒为空：admin.js:78、99、324 都用 lottery_records.user_id = users.id 做 JOIN，但抽奖记录 user_id 恒为 0（匿名）→ JOIN 不出人，看板「中奖名单」和两份 Excel 导出大概率为空。
  • 抽奖随机性：Math.random() 选奖，要测「库存为0 / 券用完」得用 seed 或 admin 接口把库存 / 券池降到 0。
这 3 条请你拍板是「设计如此」还是 bug，我再定用例预期（验证 / 标注 // TODO 当前不通过）。

大白话版：这段方案到底在说啥

给 y 的直白讲解

下面用大白话把这页在讲的事，一件一件说清楚。术语看不懂，就看这段。

🤖

1. 端到端测试（e2e）是啥？

就是你这抽奖网站，现在全靠人肉点。哪天改了一行代码，"拆盲盒"按钮悄悄坏了你不知道，直到有人抽了个寂寞才发现。

e2e = 雇个机器人，用真浏览器像真人一样把每个按钮点一遍——输工号、点拆盒、看奖品、填领奖、进后台加人、导 Excel……点完自动告诉你"这俩地方挂了"。等于请了个 24 小时不睡觉的质检员。

🛠

2. 为啥选 Playwright？

因为它最省事：一个工具既能"点界面"（看盲盒动画出来没），又能"查后台数据"（库存减了 1 没）。

别的工具要么只能查后台、要么配置更麻烦。就它最合适，主选它，不用再装第二个。

🧱

3. DB 隔离是啥？（最关键）

你网站所有抽奖记录、白名单、奖品库存，都存在电脑上一个叫 lottery.db 的文件里。

如果机器人测试时直接动这个真文件，会把你正在用的真实数据搞乱（比如把奖品库存抽光）。

我的第一件事：让测试用一份临时草稿本（空库副本），绝不碰真本。改 5 行代码加个"开关"实现，你平时用完全不受影响。

📋

4. 那 ~20 条"用例"是啥？

就是把网站能干的事，一条条列成"该长这样"的清单，让机器人照着验：

玩家端 7 条：页面能开、白名单内能抽、不在名单灰色提示、抽完出奖品卡、选领取方式能提交、库存抽光提示、券用完提示 管理端 7 条：登录（错密码拦）、看板数字对、中奖名单有数据、加人删人、Excel 导入、重置、导出领奖 Excel 对账 3 条：抽一次库存 -1、重置能恢复、同人不能连抽两次
⚡

5. 顺手发现的 3 个"坑"

看代码时我看出三个地方目前不对劲，一写测试就露馅：

防重复没生效：写着"同工号只能抽一次"，实际抽完不锁人，理论上能一直抽 中奖名单可能空的：后台名单/导出 Excel 靠"中奖记录对人"，但记录没记是谁抽的 → 对不上 → 大概率空 抽奖是随机的：每次中哪个随机，测试只能验"出了奖+库存减"，不能指定某个奖；验边界得先塞测试数据

这 3 个要你拍板：故意设计的，还是真 bug 要修？

⏱

6. 要多久？能自动跑吗？

大概 1.5–2 天活（分 P0–P5 阶段）。

最后还能接上自动跑：你每次改代码，机器人自动测一遍，挂了立刻报警。等于给网站装了个 permanent 质检岗。

一句话：给抽奖网站请个机器人质检员，先用草稿本隔离不碰真数据，照 20 条清单逐项点，顺便把你那 3 个隐藏 bug 揪出来。

✅
