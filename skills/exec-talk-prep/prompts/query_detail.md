# 坑点 / 把关清单查询（query_detail）

> 用途：用户查询「发言人稿件要检查什么」「主持稿有哪些坑」「谈参怎么把关」等。

## 发言人稿件把关清单（prep_sop）
| 细项 | 责任人 | SLA / 完成标准 | 来源 |
|------|--------|---------------|------|
| 会议框架 | BP | 提前 ≥1 周，和 BP leader 对齐 | 原始数据 |
| 发言人稿件把关（含基干/员工/主持人逐字稿） | BP&ABP | 材料与逐字稿把关 | 原始数据 |
| QA 收集 | BP | 提前 ≥1 周回收，对齐问答建议&老板分工 | 原始数据 |
| 高管谈参 | （建议 BP&ABP） | Dowson/线负责人/GM 发言要点 | 原始数据 |
| 高管照片 & 职位描述 | ABP | 提前与秘书对齐并确认描述 | 原始数据 |
| 参会指引 | BP | 提前 ≥3 天，对齐&发送相关方 | 原始数据 |

## 高频坑点（pitfalls）
1. 职位描述未与秘书确认 → 现场写错（CEO 写成 CE0）
2. 谈参未对齐老板分工 → QA 答非所问 / 踢皮球
3. 主持人未彩排 → 与控台卡、冷场（需 2-3 次，半脱稿）
4. 逐字稿未脱稿 → 念稿感重（talker 全脱稿）
5. 线上互动只发二维码 → 体验差（应发链接）
6. 保密漏提 → 截屏录屏外泄（纪律段必含）
7. 高管发言口径未本人确认 → 失真/合规风险

## 使用方式
- 用户问具体环节 → 从 prep_sop / host_script_elements 取对应项 + 完成标准。
- 用户问"有什么坑" → 直接列 pitfalls。
- 所有项标（原始数据），除非用户场景超出 SOP 才标（经验推断）。
