# Talent Intel Mapper — 人才情报归总

## 概述

对指定公司/行业/团队，通过公开渠道联网采集人才信息，交叉验证后输出结构化人才地图。核心原则：**只采公开可查信息，不编名字不编职位，查不到标"需确认"，重名单列不硬凑**。

## 硬约束（不可违反）

1. **只采公开源**：任命新闻、公司官网/管理层披露、HR行业大会嘉宾名单、百科、脉脉/领英公开主页片段、会议演讲、论文、开源、新闻稿。不使用内部泄露或非公开信息。
2. **不编不猜**：没有公开来源支持的名字/职位/关系，一律不写入。缺了标 `（需确认）`。
3. **每条必带**：来源链接 + 采集日期。
4. **置信度三档**：高（多源交叉一致）/ 中（单源或两源但一致）/ 低（矛盾或信息过简）。标"低"必须附"需人工核实"。
5. **重名处理**：同名不同人，单独列出，标注区分依据，不硬凑。
6. **登录墙源**：脉脉/领英/小红书个人主页通常需登录，如无法直采则标注"登录墙未能直采，以新闻/会议/百科替代"，不假装采到了。

## 工作流程

### 第一步：澄清锚点（必须完成才开搜）

没有可锚定的节点集合就不开搜——否则会变成泛搜编造。必须拿到以下之一：

| 锚点类型 | 示例 | 说明 |
|---------|------|------|
| 具体公司名 | "字节跳动""智元机器人" | 以公司为锚，沿公开可查的同事/上下级关系向外扩 |
| 具体行业赛道 | "AI大模型""商业航天""出海" | 横向扫赛道头部玩家关键岗位 |
| 种子名单 | 3-5 个人名 | 以人为锚，沿公开关系网扩展 |
| 具体职能+范围 | "新兴行业HR从业者" | 需进一步限定到可搜的赛道集合 |

**若用户给的描述太宽（如"人力资源行业+1-5年"），必须追问到可锚定范围再开搜。最多追问 2 轮，第 3 轮直接以最合理默认范围开搜并标注"采样版"。**

### 第二步：并行铺搜

根据锚点类型选择搜索维度模板，同时开 4-6 个 WebSearch：

**公司锚点搜索维度：**
1. 核心管理层/高管名单（"{公司名} 核心管理层 高管名单 {年份}"）
2. 组织架构调整（"{公司名} 组织架构 调整 业务线 {年份} 晚点 36kr"）
3. HR线负责人（"{公司名} 人力资源负责人 CHO HRVP {年份}"）
4. 业务线负责人（"{公司名} {具体业务线} 负责人 {年份}"）
5. 补充业务线（"{公司名} 其他BU 负责人 {年份}"）
6. 商业化/电商线（"{公司名} 电商 商业化 负责人 {年份}"）

**行业锚点搜索维度：**
1. 行业任命新闻（"{赛道} 任命 {职位} {年份}"）
2. HR行业大会嘉宾（"HR行业大会 演讲嘉宾 {赛道} {年份}"）
3. 新兴赛道补充（"{细分赛道} {职位} 任命 {年份}"）
4. 出海/国际化（"{赛道} 出海 {职位} {年份}"）

详见 `references/search-dimensions.md`。

### 第三步：多源交叉验证

对搜索结果中出现的每个人物，按 `references/source-priority.md` 的源优先级体系判断置信度：

- **高**：≥2 个独立公开源一致确认（如 官网+新闻、新闻+百科、大会嘉宾+公司公告）
- **中**：1 个可靠源，或 2 个较弱源一致
- **低**：来源矛盾、信息过简、或仅有单一弱源 → 必须标"需人工核实"

**矛盾处理**：同一人在不同来源中职位不同时，两源都记录，标"低·需人工核实"，写明矛盾点。

### 第四步：组装条目

每条人物信息按以下字段组装：

```
| 姓名 | 职位 | 所在团队/业务线 | 公开简介 | 来源链接 | 采集日期 | 置信度 |
```

- **公开简介**：1-2 句，包括履历亮点、公开演讲/报道中的关键信息
- **来源链接**：必须是可直接访问的 URL
- **采集日期**：当天日期（YYYY-MM-DD）

### 第五步：关系梳理

识别三类公开关系：

| 关系类型 | 说明 | 置信度判定 |
|---------|------|-----------|
| 上下级 | A 向 B 汇报（公开报道/架构图） | 多源确认=高；单源=中；推测=低 |
| 同事 | 同一公司/团队共事 | 公开报道=高；仅推断=中 |
| 权力消长 | 架构调整中的升降（接管/让出/合并） | 有明确时间线=高；模糊=中 |

关系图以文字描述形式呈现：`A →(汇报)→ B →(接管)→ C 的业务`

### 第六步：缺口披露

在交付物末尾列出所有未能确认的信息：

- 标 `（需确认）` 的条目
- 置信度为"低·需人工核实"的条目
- 登录墙未能直采的源说明
- 信息过时风险提示（"此为 YYYY-MM-DD 采集时点公开源快照"）

### 第七步：双交付

输出两份文件到工作目录：

1. **HTML 卡片墙**（主展示）：紫青配色 Bento 卡片 + 可按行业/业务线/置信度筛选 + 关系网络文字图 + 缺口提示区。详见 `references/output-spec.md`。
2. **Markdown 表格**（数据版）：结构化表格，可直接进 Obsidian 或复制粘贴。
