# 文化活动 · 主持稿 + 谈参 准备助手（通用版）

## 这个 skill 解决什么

文化活动里「写给人看的高管内容」和「主持人串词」是最难、最容易踩坑、又最高频的两类交付：

- 谈参写偏 → QA 环节答非所问 / 互相踢皮球
- 职位描述没和秘书确认 → 现场职位写错（如 CEO 写成 CE0）
- 主持稿没彩排 → 与控台配合卡、冷场
- 保密要求漏提 → 截屏录屏外泄
- 互动设计踩关系红线 → 上下级场合用了平级朋友向破冰，尴尬
- 主持稿写成「舞台监督提示单」→ 满屏括号、没温度、不通顺

本 skill 把多份真实文化活动主持稿抽象成**通用方法论资产库**（话术、衔接、互动、骨架、物料、真腔、救场），让你按场合 10 分钟产出一版**干净、有温度、可读**的初稿 + 把关清单。**所有部门 / 公司 / 人名 / 奖项均为占位符，由你填。**

> 这是通用对外版，已去除任何具体部门名、公司项目名。如果你需要带本厂真实腔调的内部版，请用 `exec-talk-prep`（个人私有 skill）。

## 两个模块

| 模块 | 触发示例 | 产出 | 模板 |
|------|----------|------|------|
| **A. 主持稿** | "写一份{部门}员工大会主持稿，主题{主题}" / "双人主持" | 干净口语化串词（单主持 / 双主持脱口秀式） | `prompts/draft_host_script.md` |
| **B. 谈参** | "给{领导}准备一份{场合}谈参 / 致辞稿" | 高管谈参（目标分层 + 四要素）+ 致辞逐字稿（轻量版，无 QA 预案库） | `prompts/draft_talk_prep.md` |

## 数据来源 / 语料

- `references/asset_library.json` —— 核心资产库：通用话术 6 类、环节衔接 6 模式、互动导入 12 手法（带成本 × 适用关系标签）、活动骨架 3 套、物料清单 7 项，外加 `generation_rules`（音色 / 隐喻 / 情绪曲线 / show-don't-tell / cue 规范 / 占位符纪律）。
- `references/corpus.md` —— 9 份真实主持稿的**抽象化场景摘要**（已去私有部门名），作为 few-shot 语料说明。
- `references/raw-corpus/` —— **脱敏后的原始主持稿全集**（7 份 docx；1 份扫描件 PDF 因无法自动脱敏未纳入）。部门 / 公司 / BG 已替换为 `{部门}`/`{公司}`/`{BG}` 占位；文中人名为原稿真实姓名，仅作语气 / 结构参考，对外使用时请自换 `{姓名}`/`{领导}`。供对照资产库理解真实腔调（**不宜直接对外发布**）。
- `references/voice_samples.md` —— **脱敏真腔样本**，供模仿语气（开场温度 / 承上启下 / 轻自嘲 / 互动接话 / 颁奖节奏 / 结尾收束），不带私有信息。
- `references/save_scene.md` —— **救场话术库**，临场口头短句（冷场 / 超时 / 尖锐回答 / 设备卡 / 情绪两极）。
- `references/talk_prep_assets.json` —— **谈参专属资产库（轻量版）**：目标分层（员工/高管/部门三档）、核心信息四要素（定调/肯定/战役/CTA）、致辞骨架（开场/主体/收尾 + 场景节奏）。**不含**重型 QA 预案 / 坑点检查 / 保密纪律库，适合低风险内部场合。
- `prompts/draft_host_script.md` —— 主持稿生成规范 + 模板（两遍生成 / 成品硬规则 / 自检闸 / **双主持脱口秀式变体**）。
- `prompts/draft_talk_prep.md` —— 谈参 / 致辞模板（3 样资产轻量版）。

## 两遍生成（强制，解决"满屏括号 / 没温度"）

1. **第一遍 · 规划（不出现在成品）**：读 `asset_library` + `voice_samples`，按活动类型套 `activity_skeletons`，从 `interaction_methods` 选 2–4 个（`relation` 仅 supervisor / exec），定一个隐喻意象，设计情绪起伏（内部用，不打印到成品），列出占位。这一步只在你脑内完成。
2. **第二遍 · 交付**：只写干净口语脚本。读者看不到任何规划痕迹。

## 成品硬规则（违反即不合格）

1. **零元标注**：成品禁止出现 `(通用模板)` `(示例)` `(需确认)` `[引用iX]` 这类标记。它们是给你看的，不是给主持人的。
2. **cue 单行**：舞台提示用 `【cue: …】` 独占一行，绝不黏在口语句前。
3. **音色 + 温度**：口语化、有呼吸感，像真人在台上说；用「咱们 / 大家」拉近距离；可轻自嘲、可共情；禁书面腔、禁排比堆砌、禁反引号当强调。**温度来自写法（口语 / 自嘲 / 共情视角 / 呼吸感），不来自真实数据**——纯语气温度句（如静音提醒、难得凑这么齐、那差掉的 3 分）与占位无关，无论是否提供真实参数，都要全程保留并强化。
4. **隐喻贯穿**：开场选一个与主题契合的比喻（破局→棋局/航线，对齐→地图），全篇用同一意象做钩子回扣；主题未知时用 `{隐喻意象}` 占位并在待填清单提示「依主题定」。
5. **情绪曲线（规划层内部，不打印）**：在脑内为每节设计情绪目标与能量起伏（破冰→张力→发散→收敛→升华→回暖），让内容节奏自然带出；**成品不打印能量行**。
6. **互动演出来**：互动环节给一段「示例问答 + 接话扣题」，不只写「每人写一张…」的指令。
7. **占位 + 示例提示（不杜撰又有温度）**：真实参数未提供时全部用 `{ }` 占位，**绝不编造**真实活动信息。占位处用「占位 + 示例提示」双标注展示写法与温度，例如 `{隐喻意象｜如：破局→棋局 / 航线}`、`{礼物名｜如：定制扇子}`；互动示例用明确标注的「模板示范 / 写法示范」具象故事（如「（读一条示例｜模板示范：有次商机晾了三天…正式稿替换）」）——用户一眼能区分「占位 = 要填的」「模板示范 = 写法参考」，既展示共情温度又不冒充真实活动。
8. **混合会场**：异地打招呼用**双向挥手**（现场朝镜头挥、线上在自己画面挥），或确认线上视频已投大屏；绝不写单向「让我们看见你」。
9. **双产物输出**：主持稿与谈参交付均 = ① **Markdown 干净稿**（两遍生成成品）+ ② **HTML 三色阅读版**（见下）。两者内容一致，HTML 是阅读辅助。

## HTML 三色阅读版（强制输出，渲染规范）

适用于**主持稿与谈参**两种产物。基于 Markdown 干净稿生成一份 self-contained HTML，方便看稿、念稿：

- **句句换行**：每句话（以 。！？ 收尾）单独成一行，念稿一行一拍；`【cue】` 舞台指令用浅灰块单独标，不混三色。
- **三色标注**（仅阅读辅助，不改正文）：
  - 🟠 **橙色** = 有温度的语气词 / 口语共情句（静音提醒、难得凑齐、自嘲、拉近距离句）。
  - 🔵 **蓝色** = 每一节标题（## 节标题）。
  - ⚪ **灰色小字** = 括号里的舞台提示 / 备注（（笑）（点头）（合影）等）。
- **页脚**：注明「颜色仅为阅读辅助标注，不影响正文」。**本 skill 生成的 HTML 一律不带 yitong 页脚**（这是工具产物，非个人沉淀发布）。
- 内容完全照搬干净稿，只加标记不改字；无杜撰真实活动参数。

## 受众分层硬约束（必读，不可违反）

文化活动互动 / 破冰 / 串词必须按**受众关系**分层，绝不混用：

- ① 平级 / 朋友向（peer）：轻松、可暴露、可搞笑 —— **本 skill 不产出此类内容**
- ② 领导 ↔ 员工（上下级，supervisor）：尊重、不隐私暴露、建信任不越界 —— ✅ 支持
- ③ 领导 ↔ 领导（高管间，exec）：商务化、以专业 / 共同目标切入 —— ✅ 支持

`asset_library.interaction_methods` 中每个手法都标了 `relation` 字段（supervisor / exec）。生成时**只选②/③**，自动剔除①。凡关系标注含 peer 的手法一律不可用。

## 编写原则

1. **占位符保留人工所有权**：人名 / 奖项 / 主题 / 部门用 `{ }` 占位，AI 不编造真实姓名与奖项。
2. **去私有化**：不写死任何真实部门名、公司项目名、内部黑话；用 `{部门}` `{公司}` `{产品线}` 占位。
3. **先骨架后填充**：先按活动类型套 `activity_skeletons`，再填话术与互动。
4. **互动占比**：员工大会建议 ≥ 2 个互动环节；Offsite 以研讨 + 沉淀为主；颁奖以节奏把控为主。
