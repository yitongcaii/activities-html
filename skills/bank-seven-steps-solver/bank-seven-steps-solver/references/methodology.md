# 七步成诗法（Seven Steps Problem Solving）方法论参考

> 本文档基于麦肯锡核心技能培训材料整理，作为七步成诗问题解决助手的方法论参考。
> 更新版本：v2.0 — 补充培训PPT详细方法论内容

---

## 总览

解决问题的基本方法——"七步成诗法"：

```
第一步: 界定问题         ← 思考模式
第二步: 分解问题（逻辑树） ← 思考模式
第三步: 优先排序（漏斗法） ← 思考模式
第四步: 工作计划         ← 行动模式
第五步: 关键分析         ← 行动模式
第六步: 归纳建议         ← 行动模式
第七步: 交流沟通         ← 行动模式

循环反复，重头再来 → 衡量结果是否成功，然后从第一步重新做起
```

**关键：** 这七步不是线性的，而是**循环往复**的过程。在任何一步发现新信息或问题定义不准确时，都应回到之前的步骤重新审视。

## Step 1: 界定问题

### 1.1 为什么界定问题如此重要

对问题有清晰明确的认识是能够成功解决问题的前提。一个问题常常有很多不同的症状，需要清楚地区分什么是问题的症状，什么是问题的根本原因。

**常见陷阱**：
- 把症状当作问题（如「市场份额下降」是症状，而非问题根因）
- 问题定义过于宽泛或过于狭窄
- 没有与决策者达成一致
- 过早跳入解决方案而未充分理解问题

### 1.2 SMART 原则（详细版）

问题的最终界定必须是明确且可执行的：

| 原则 | 含义 | 检验标准 | 示例 |
|------|------|---------|------|
| **S**pecific | 具体而不空泛 | 能否用一句话描述？是否包含时限和预期效果？ | "信用卡业务"→"信用卡新客获取" |
| **M**easurable | 成功标准可衡量 | 是否有定量或定性的衡量指标？ | "提升3个百分点"而非"提升份额" |
| **A**ctionable | 以行动为导向 | 是否指向具体可执行的行动？ | 不是"行业竞争激烈"而是"如何应对竞争" |
| **R**elevant | 相关 | 与核心业务目标的关联是否清晰？ | 与零售转型战略直接相关 |
| **T**ime-framed | 有时限性 | 是否明确了解决期限？ | "2026年底前"而非"尽快" |

**SMART 检验方法**：将问题陈述写出来后，逐项检查每个SMART维度是否满足。如果有任何一项不满足，需要继续追问和完善。

### 1.3 问题陈述表（Problem Statement）— 五要素模型

标准的问题陈述表包含**五个核心要素 + 一个核心问题**：

```
┌─────────────────────────────────────────┐
│           问题陈述表                      │
│  ┌────────────────────────────────┐      │
│  │        核心问题                 │      │
│  │ （一句话，具体、含时限和效果）    │      │
│  └────────────────────────────────┘      │
│                                          │
│  ① 现状/背景        ② 决策者和相关方     │
│  ③ 成功标准         ④ 解决方案范围       │
│  ⑤ 限制因素                              │
└─────────────────────────────────────────┘
```

1. **现状/背景**：对面临情况及其复杂性进行评论（如行业趋势、竞争态势）
2. **决策者和相关方**：
   - 决策者：决定是否采纳建议的人
   - 相关方：需要在解决方案中考虑到其意见和建议的人
3. **成功的标准**：明确的用定量或定性的方式，衡量建议是否应该被采纳
4. **解决方案的范围**：说明解决方案应该包括或不包括什么（边界非常重要）
5. **解决方案所受的限制**：确定解决方案所受到的限制，如资源限制、时效限制、外部监管限制等

**核心问题**（置于陈述表最中心）：非常简洁的一句话阐述问题，描述越具体越好，包括界定解决问题的时限和需要达到的效果，但是不能过于狭隘到导致错误。

### 1.4 界定问题的诀窍

1. 始终让管理层和决策者参与
2. 频繁沟通，让参与问题界定的各方都能达成一致
3. 不要害怕在过程中重新界定问题的范围
4. 在问题界定过程中并不需要知道所有问题的答案
5. **区分症状和问题**：反复追问"为什么"来找到根因

### 1.5 界定问题是往复循环的过程

```
确定需要开展一个项目
    → 第一次问题界定
    → 与问题解决方案的主要受益者(Sponsor)探讨
    → 修改问题界定
    → 和主要决策者一起检查问题界定，并达成一致
    → 修改问题界定
    → 和其余的利益相关方对问题的界定进行探讨，并达成一致
    → 清晰的问题界定，明确的目标
```

## Step 2: 分解问题（逻辑树）

### 2.1 什么是逻辑树

逻辑树是将问题层层分解为子议题的工具。核心原则是 MECE。它帮助你：
- 将复杂问题拆解为可管理的小块
- 确保分析的完整性
- 为团队分工提供清晰的框架

### 2.2 MECE 原则（详细版）

**M**utually **E**xclusive, **C**ollectively **E**xhaustive（相互独立，完全穷尽）

- **相互独立（ME）**：每个子议题之间没有重叠，相互之间是独立的
  - 检验方法：如果改变某一个子议题的结论，是否会影响其他子议题？如果不影响，则独立。
- **完全穷尽（CE）**：所有子议题加在一起能够完全覆盖整个问题，没有遗漏
  - 检验方法：是否存在不属于任何子议题的情况？如果不存在，则穷尽。

**MECE 检查方法**：
1. 检查各子议题之间是否存在概念重叠
2. 检查所有子议题合在一起是否涵盖了问题的全部方面
3. 每个子议题是否可以独立分析和验证
4. 分解是否具有一致性（同一层级的分解维度一致）

### 2.3 五种典型的逻辑树结构

| 类型 | 说明 | 适用场景 | 示例 |
|------|------|---------|------|
| **经营体系分解** | 按公司各职能分解 | 组织效率提升 | 前台/中台/后台 |
| **数学公式分解** | 用数学公式分解 | 财务类问题 | 利润=收入-成本；ROE=ROA×杠杆 |
| **成本项目分解** | 按成本类别分解 | 成本优化 | 人力/物力/资本/合规成本 |
| **时间维度分解** | 按时间周期分解 | 战略规划 | 短期(1年)/中期(2-3年)/长期(3-5年) |
| **个数×单价分解** | 按量价分解 | 收入增长 | 收入 = 客户数 × 户均贡献 × 转化率 |

### 2.4 好的逻辑树的四个特征

1. **所有下属问题符合 MECE**：各分支不重叠、不遗漏
2. **问题层层细分**：直到每个子议题都可以被独立分析
3. **相似性质的问题归纳统一**：在同一主要问题下
4. **分解具有一致性**：同一层级采用相同的分解维度

### 2.5 逻辑树分解深度

- **第一层（L1）**：3-5 个核心维度，代表问题的主要方面
- **第二层（L2）**：每个 L1 下 2-4 个子议题
- **第三层（L3）**：仅在必要时细分，确保可以直接对应到分析行动
- **总计**：一般不超过 3 层，总共 15-25 个末端议题为宜

## Step 3: 优先排序（漏斗法）

### 3.1 目的

去除不重要的议题可以帮助节省大量的时间，让精力集中在最重要的议题上。**不是所有问题都值得分析——关键是找到杠杆点。**

### 3.2 核心原则

- **80/20 法则（帕累托法则）**：20% 的议题往往能解决 80% 的问题
- **优先排序是艺术与科学的结合**：做出最佳判断
- **反问测试**：如果我做了/不做……，那又会怎么样？同时提醒自己是否遗忘了什么
- **重要性矩阵**：将议题映射到二维空间，快速可视化优先级

### 3.3 2×2 优先矩阵（详细版）

使用两个维度评估每个议题：
- **X 轴：影响重要性**（低 → 高）：解决该议题对核心问题的贡献度
- **Y 轴：可行性**（低 → 高）：在现有资源和时间内的实现难度

```
                影响重要性
          低 ────────── 高
     高 ┌─────────┬──────────┐
        │ 快速解决  │ ⭐ 优先处理 │
可行性   │         │           │
     低 ├─────────┼──────────┤
        │ 暂时搁置  │ 重点规划   │
        │         │           │
        └─────────┴──────────┘
```

| 象限 | 影响 | 可行性 | 策略 | 行动 |
|------|------|--------|------|------|
| 右上 | 高 | 高 | ⭐ 优先处理 | 立即启动，投入主力 |
| 左上 | 低 | 高 | 快速解决 | 快速完成，不投入过多资源 |
| 右下 | 高 | 低 | 重点规划 | 制定详细计划，分步实施 |
| 左下 | 低 | 低 | 暂时搁置 | 纳入观察清单，暂不行动 |

### 3.4 优先排序的注意事项

- 不要因为"可行性低"就放弃高影响议题——应制定计划分步突破
- 优先排序后，集中 80% 的资源在前 20% 的议题上
- 定期回顾优先级，因为环境和条件会变化

## Step 4: 工作计划

### 4.1 工作计划的核心要素

一份好的工作计划表应包含：
- **工作内容**：具体要做什么
- **最终成果**：预期交付物
- **负责人**：谁来做
- **时间安排**：按周/按阶段的甘特图
- **依赖关系**：任务之间的先后依赖

### 4.2 议题分析工作表

每个优先议题都应有一张工作表：

| 字段 | 说明 | 作用 |
|------|------|------|
| **问题** | 需要回答的具体问题 | 明确分析目标 |
| **初始假设** | 对答案的初步判断 | 假设驱动分析 |
| **支持依据** | 已知的支持事实/数据 | 建立分析基础 |
| **求证方法** | 验证假设的分析方法 | 规划分析路径 |
| **所需信息** | 需要获取的数据 | 明确数据需求 |
| **信息来源** | 数据从哪里获取 | 规划数据采集 |
| **负责人** | 谁来执行 | 明确责任 |
| **时间** | 预计完成时间 | 控制进度 |
| **预期成果** | 分析完成后的交付物 | 结果导向 |

### 4.3 制定工作计划前的 5 个自检问题

1. **目标和最终成果**是否明确界定？
2. 是否所有的分析都十分**必要**，是否充分回答了问题？
3. 是否明确了**下一步工作**？分析是否实际？
4. 是否明确了**责任和时间**要求？
5. 时间安排是否符合更大**项目的要求和重点**？

## Step 5: 关键分析

### 5.1 议题分析六大最佳做法

1. **基于假设并重视最终成果**：
   - 用假设来寻找数据，用数据来论证假设
   - 不是"先收集数据再看结论"，而是"先有假设再去验证"
2. **先估后细**：
   - 在开展细节分析之前，先对问题的轻重缓急进行估算
   - 避免在不重要的数据上浪费时间
3. **二八原则和逆向思维**：
   - 聚焦最关键的 20% 分析
   - 从结论出发倒推需要什么论据
4. **使用专家作为数据来源**：
   - 善用内外部专家的判断和经验
   - 专家访谈可以快速验证或推翻假设
5. **与小组分享**：
   - 及时沟通发现，避免重复劳动
   - 集体智慧优于个人分析
6. **勇于创新**：
   - 不拘泥于传统分析方法
   - 用新角度看老问题

### 5.2 假设驱动分析法

```
形成初始假设 → 设计分析验证 → 收集数据 → 验证/推翻假设 → 修正假设 → 循环
```

**关键**：假设不是结论，是待验证的猜想。好的假设应该是：
- 可验证的（有方法去证实或推翻）
- 具体的（不是笼统的判断）
- 有行动指向的（验证后能指导决策）

## Step 6: 归纳建议（金字塔原理）

### 6.1 金字塔原理概述

金字塔原理是一种**自上而下的**结构化表达方法：
- 先给结论（中心思想）
- 再给支撑论点（主线）
- 最后给证据（支持论据）

```
         ┌──────────┐
         │ 中心思想  │  ← 回答核心问题的一句话
         └────┬─────┘
     ┌────────┼────────┐
  ┌──┴──┐ ┌──┴──┐ ┌──┴──┐
  │主线1│ │主线2│ │主线3│  ← 3个核心支撑论点
  └──┬──┘ └──┬──┘ └──┬──┘
  ┌──┴──┐ ┌──┴──┐ ┌──┴──┐
  │支持  │ │支持  │ │支持  │  ← 数据和事实
  └─────┘ └─────┘ └─────┘
```

### 6.2 金字塔六步构建法

1. **列出你想表达的所有观点**：头脑风暴，不做筛选
2. **找出各观点之间的逻辑关系**：归类、分组、排序
3. **得出结论（中心思想）**：综合所有观点，提炼核心
4. **检查中心思想**：是否回答了决策者的关键问题
5. **检查主线是否 MECE**：紧密、无重叠地支持中心思想
6. **检查支持论据**：是否充分且基于事实

### 6.3 金字塔检查清单

**中心思想**：
- ☐ 回答沟通对象的关键问题，为决策或行动提供方向
- ☐ 提炼而不是信息罗列总结
- ☐ 以简单的语言准确表达
- ☐ 一句话可以概括

**主线（主要支撑点）**：
- ☐ 紧密、无重叠地支持中心思想（MECE）
- ☐ 实用、面向行动/解决方案
- ☐ 每个支撑要素提炼综合了下面的支持论据
- ☐ 所有的支撑要素属于同一个层次，并且按逻辑顺序排列
- ☐ 使用与沟通对象一致的语言
- ☐ 完整的观点陈述表达，而非简单的主题

**支持（细节）**：
- ☐ 相关、充分并且基于事实
- ☐ 充分支持上一层的主要观点
- ☐ 在同一支撑要素下，不同支持观点是同一逻辑类型（例如：原因、行动）

## Step 7: 交流沟通

### 7.1 故事板（Storyboard）

从金字塔到故事板的转换核心是构建**叙事逻辑**：

**故事线逻辑**：情境 → 冲突 → 疑问 → 回答（SCQA结构）

- **情境**（Situation）：大家都知道的背景
- **冲突**（Complication）：出了什么问题/发生了什么变化
- **疑问**（Question）：所以我们该怎么办？
- **回答**（Answer）：我们的建议是...

**故事板搭建要领**：
- 通过把各个图表的标题连接成一个有逻辑和说服力的故事
- 每张图表的标题本身就应该讲述故事（结论性标题而非描述性标题）
- 先写故事板再做图表，不是先做图表再拼故事

### 7.2 30 秒电梯推销

将金字塔的中心思想和主线浓缩为 30 秒以内可以阐述完毕的核心信息：

**结构**：
1. 一句话说明问题背景
2. 一句话给出核心结论
3. 三句话说明核心发现/建议（对应金字塔主线）
4. 一句话说明建议的下一步行动

**总计 6 句话，约 25-30 秒**

### 7.3 沟通的关键原则

1. **了解你的听众**——使用对方熟悉的语言
2. **先给结论**——不要让听众猜测你要说什么
3. **数据说话**——用事实和数据支撑每个观点
4. **行动导向**——每个建议都应指向具体的行动
5. **简洁明了**——去掉不必要的信息，保留核心
6. **结论性标题**——每页PPT的标题应该是结论而非描述

## 银行业常用分解框架

以下是银行业务问题中常用的逻辑树分解框架：

| 问题类型 | 推荐分解框架 | 示例 |
|---------|------------|------|
| 收入增长 | 收入 = 客户数 × 户均AUM × 收益率 | 按产品线/渠道/客群分解 |
| 成本优化 | 人力成本 + IT成本 + 运营成本 + 合规成本 | 按成本项目分解 |
| 市场份额 | 按区域/产品/客群分解 | 价值链分解 |
| 客户体验 | 获客→激活→留存→变现→推荐（AARRR） | 用户生命周期 |
| 风控优化 | 贷前(准入)→贷中(监控)→贷后(催收) | 风控流程分解 |
| 数字化转型 | 前台(渠道)+中台(数据/风控)+后台(运营) | 经营体系分解 |
| 组织效率 | 组织架构×流程效率×人才能力×激励机制 | 多维度交叉 |
| 利润分析 | 利润=收入-成本；ROE分解树 | 数学公式分解 |

## 银行业应用案例框架

### 案例 1：如何提升信用卡业务市场份额

**问题分解示例**（逻辑树）：
```
提升信用卡业务市场份额
├── 提升获客能力
│   ├── 线上渠道获客
│   ├── 线下网点获客
│   └── 合作伙伴渠道
├── 提升客户价值
│   ├── 提升交易频次
│   ├── 提升客单价
│   └── 提升分期比例
├── 降低客户流失
│   ├── 提升客户满意度
│   ├── 优化权益体系
│   └── 改善服务体验
└── 优化成本结构
    ├── 获客成本优化
    ├── 运营成本优化
    └── 风险成本控制
```
