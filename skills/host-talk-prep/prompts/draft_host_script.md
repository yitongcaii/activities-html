# 主持稿生成规范（先读，再写）

## 两遍生成（强制）

- **第一遍 · 规划（不出现在成品）**：读 `asset_library` + `voice_samples`，按活动类型套 `activity_skeletons`，从 `interaction_methods` 选 2–4 个（`relation` 仅 supervisor / exec），定一个隐喻意象，设计情绪起伏（内部用，不打印到成品），列出占位。这一步只在你脑内完成。
- **第二遍 · 交付**：只写干净脚本。读者看不到任何规划痕迹。

## 成品硬规则（违反即不合格）

1. **零元标注**：成品禁止出现 `(通用模板)` `(示例)` `(需确认)` `[引用iX]` 这类标记。它们是给你看的，不是给主持人的。
2. **cue 单行**：舞台提示用 `【cue: …】` 独占一行，绝不黏在口语句前。例：`【cue: 候场轻音乐起】`。
3. **音色**：口语化、有呼吸感，像真人在台上说；用「咱们 / 大家」拉近距离；可轻自嘲、可共情；禁书面腔、禁排比堆砌、禁反引号当强调。
4. **隐喻贯穿**：开场选一个与主题契合的比喻（破局→棋局/航线，对齐→地图），全篇用同一意象做钩子回扣，增强记忆点。
5. **情绪曲线（规划层内部，不打印）**：在脑内为每节设计情绪目标与能量起伏（破冰→张力→发散→收敛→升华→回暖），让内容节奏自然带出起伏；**成品不打印能量行**。
6. **互动演出来**：互动环节给一段「示例问答 + 接话扣题」，不只写「每人写一张…」的指令。
7. **占位 + 示例提示（不杜撰又有温度）**：真实参数未提供时全部用 `{ }` 占位，**绝不编造**真实活动信息。占位处用「占位 + 示例提示」双标注展示写法与温度，例如 `{隐喻意象｜如：破局→棋局 / 航线}`、`{礼物名｜如：定制扇子}`；互动示例用明确标注的「模板示范 / 写法示范」具象故事（如「（读一条示例｜模板示范：有次商机晾了三天…正式稿替换）」）——用户一眼能区分「占位 = 要填的」「模板示范 = 写法参考」，既展示共情温度又不冒充真实活动。纯语气温度句（静音提醒、难得凑齐、自嘲、那差掉的 3 分）与占位无关，无论是否提供真实参数都要全程保留并强化。

## 混合会场机制（重要）

异地打招呼要「现场看见线上手势」，须确认线上视频流已投大屏；否则用**双向挥手**（现场朝镜头挥、线上在自己画面挥）。绝不写单向「让我们看见你」。

## 受众分层

互动只选 `relation=supervisor / exec`，自动剔除 `peer`（平级朋友向）。

## 双主持变体（脱口秀式）

**触发**：用户说「双人 / 双主持 / 两人主持 / 搭档主持」时启用；否则默认单主持。

**角色分工**：
- **甲（控场稳）**：定调、引介下一位发言人、承上启下、收束。语气稳、准、有分量。
- **乙（活泼接梗）**：破冰、互动引导、轻自嘲、拉近距离。语气松、暖、会抛梗。

**写法要点**：
- 开场互损 / 互捧破冰（如乙：「今天我负责把场子暖热，甲负责在关键时刻把大家拉回正事。」甲：「……所以正事交给我，玩笑交给她。」），但温度与尊重不丢，不踩关系红线。
- 串场分工：甲收上一节、乙开下一节，或反之；每段交接用一句「甩梗 / 接梗」过渡。
- 隐喻回扣两人接力：同一意象可在甲乙间交替出现（甲点题、乙展开），增强记忆点。
- 互动环节由乙主导引导，甲补位收束。
- 台词标注：在 `主持人：` 后标明 `{甲}` / `{乙}`，cue 仍是 `【cue: …】` 独占一行；占位符与单主持一致。

**示例（开场片段）**：
```
【cue: 候场轻音乐起】
{甲}：（微笑，等静下来）先把手机调成静音吧——咱们今天聊点大事。
{乙}：我是{乙名}，今天跟我搭档的是{甲名}。他负责把大家拉回正事，我负责……把正事讲得不那么像正事。
{甲}：那开场就交给你，暖场你来。
{乙}：来，除了{现场城市}现场，线上{城市列表}的伙伴也在——镜头两边，把手举起来挥一挥！
```

# 主持稿 · {活动类型} · {主题}

## 1. 暖场

【cue: 候场轻音乐起】
主持人：
（微笑，等会场静下来）
先把手机调成静音吧——咱们今天要聊点大事，别让通知声把灵感打断了。

今天有点特别，除了 {现场城市} 现场，线上 {城市列表} 的伙伴也都在。来，镜头两边，把手举起来挥一挥！

平时大家都在业务一线连轴转，难得凑这么齐。今天不聊琐细，就聊一件事：{主题}。

（语气放轻，像说悄悄话）我打个比方——{开场定的隐喻钩子，一句话带出全篇意象}。

## 2–7. 按 skeleton 展开

- 员工大会 / Offsite / 颁奖 的环节顺序见 `asset_library.activity_skeletons`。
- **每个互动「演出来」**：先写一句主持人引导，再给一段「示例问答 + 接话扣题」，让主持人看到真实节奏。不要只写「每人写一张…」的纯指令。
- **颁奖**用万能句：念名单 → 上台 → 颁奖 → 合影 → 留步；每轮口播一句话项目简介，分量递增。
- **结尾三件套**：金句（落地不喊口号）+ 合照（带温度 + 竞业避让提醒）+ 口号回扣主题。

## 8. 彩排备注 / 控台配合

- 物料到位 / 计时催场 / 站位动线 / 保密提醒（写进主持手卡）
- 救场话术索引：见 `references/save_scene.md`（冷场 / 超时 / 尖锐回答 / 设备卡 / 情绪两极）

## HTML 三色阅读版 · 渲染规范（强制输出）

写完 Markdown 干净稿后，基于它再生成一份 self-contained HTML，供主持人看稿、念稿。

> 标杆成品（本 skill 包内）：`examples/staff-meeting-dual-demo-colored.html`（双人脱口秀式）、`examples/staff-meeting-single-demo-colored.html`（单主持）。生成时直接对齐这两份的样式与结构。
> **页脚约定：本 skill 生成的 HTML 一律不带 yitong 页脚**，统一为「颜色仅为阅读辅助标注，不影响正文」。

**基础样式**
- 卡片白底圆角，max-width 760–780px，浅灰背景，柔和投影。
- 标题 h1 + 副标题 `.sub`（灰小字，注明「模块 A · host-talk-prep · 三色版」）。
- 节标题 h2：蓝 `#2563EB`，左侧 4px 蓝竖条。

**三色标注**（仅阅读辅助，不改正文）
- 🟠 **橙色** `#EA7B30`（`.o`）：有温度的语气词 / 口语共情句（静音提醒、难得凑齐、自嘲、拉近距离句）。
- 🔵 **蓝色** `#2563EB`（h2）：每一节标题。
- ⚪ **灰色** `#9CA3AF`（`.g`）：括号里的舞台提示 / 备注（（笑）（点头）（合影）等）；整行括号提示用灰小字。

**结构规则**
1. **句句换行**：每句话（以 。！？ 收尾）单独成 `<div class="line">` 一行，念稿一行一拍。
2. **cue 单行块**：`【cue: …】` 用浅灰块 `.cue` 独占一行，不混三色、不黏口语句。
3. **主持标签行内**：双主持台词前缀 `<span class="host">甲：</span>` / `<span class="host">乙：</span>`（行内）；单主持用 `<span class="host">主持人：</span>`。
4. **只标不改字**：内容完全照搬干净稿，只加标记；无杜撰真实活动参数。

**页脚（本 skill 约定）**：每个 HTML `</body>` 前注明「颜色仅为阅读辅助标注，不影响正文」。
