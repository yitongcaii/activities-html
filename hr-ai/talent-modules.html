岗位模型（先建标尺）

这个岗成功到底要什么能力 · 评人/筛人/培养的统一标尺

① 完整示意示例 · 云技服 HRBP（服务安全产品三中心）

从绩优者逆向萃取，写「可观测行为锚」，不是形容词；跟业务目标对齐

注：以下为「示意」数字，请代入你真实团队的绩优样本

① Must（不会就不及格）

  • 独立闭环敏感个案：能独自处理绩效争议 / 离职谈判 / 违纪，不升级到总监。行为锚：过去半年独立闭环 ≥3 起敏感个案，零升级零投诉。
  • 听得懂业务语言：能跟研发 / 产品 leader 对齐 headcount 与 HC 使用节奏。行为锚：能独立做 HC 测算并向业务解释「为什么 now / 为什么这些人」。
  • 数据找问题：能用离职率 / 入职周期 / 敬业度数据发现异常。行为锚：能独立跑出季度人力看板，并指出 ≥1 个异常（如某组离职突增）。

② Should（干得好需要）

  • 从 0 搭机制并被复用：如博闻多识式学习运营机制、AISee 沙龙式技术文化载体，做完被别中心抄走。
  • 业务主动找你：业务 leader 主动来聊组织问题（HC 卡点 / 梯队断档），不是你追着推。
  • 能解释 HR 动作的业务账：把一次培训 / 一次盘点翻译成「对交付 / 对人效」的影响。

③ Could（加分项）

  • 会用 AI 自己搭流程：如新人答辩自动化 MCP（PRD 设计 + 编排，不一定要写码）。
  • 跨事业部经验：懂一线业务语境，能跟不同 BG 的 HR 对齐。
  • 文化活动能做出记忆点：如 AI 漫剧《企鹅英雄》、57 套团建方案这类有传播力的产出。
②怎么建 · 5 步流程（带阈值）
1
定样本：取该岗 top 20% 绩优者，用「绩效 + 360 + 业务 leader 提名」三者交叉锁定，样本量 ≥5 人，且覆盖新老（避免只萃取老人习惯）。
2
BEI 行为事件访谈：每人 45–60 min，只问真实发生过的事——「讲一个你处理过最难的员工关系个案」「你最自豪的一个从 0 搭的机制」，追问 STAR（情境 / 动作 / 结果 / 你具体做了什么），记可观测动作，不记感受。
3
萃取维度 + 写行为锚：把访谈里高频出现的动作归成 6–9 个能力维度，每个维度写 3 档锚点（达标 / 优秀 / 卓越），锚点必须是「做了 X」不是「X 能力强」。
4
跟业务目标对齐：该中心明年重点是降本增效 → 模型加重「数据敏感度 / HC 管控」权重。问业务 leader：「你招这个人最怕他缺哪样？」补进 Must。
5
验证 + 更新：拿去筛 10 份简历 / 评 5 个在岗人，回测：绩优者命中率应 >70%，否则重写锚点。更新节奏：业务目标变即更新，常规半年一次。
③常见坑 · 反例
❌ 抄 JD：JD 写「沟通能力强 / 责任心强」→ 无法评人，两人谁强全凭经理感觉。
❌ 形容词当锚：把「沟通能力强」直接当维度 → 改成「能独立闭环 X 类冲突」（可观测）。
❌ 无区分度：Must 和 Should 重合（都要「独立闭环」）→ 用「不会就不及格」这把刀筛 Must，Should 是「干得好才需要」。
❌ 建完不更新：业务从扩张转降本，模型还停在「能招人」→ 标尺失效，筛出来的人不对路。
面试能直接说：「我不抄 JD，会从绩优者逆向萃取——找 top20% 做 BEI 访谈，把高频动作写成行为锚（可观测、可评），再跟业务明年的目标对齐权重，最后拿去筛人回测命中率，>70% 才算立住。建完不是终点，业务目标一变就更新。」

人才画像（再测对象）

这个人实际能干什么、缺什么、想去哪 · 多维动态档案

① 完整示意示例 · 张三（云技服风控平台 · 高级工程师）

交叉验证四维，标「隐形核心 / 高宠高危」，动态更新不静态存档

注：以下为「示意」人物与数字，请代入你真实团队的样本
① 硬能力证据（实际干过什么难事）主导风控规则引擎重构（2024），带 4 人，QPS 从 1.2w→3.5w，故障率降 40%；独立搞定 2 次 P2 故障复盘，零重复。
② 行为信号（360 / ONA 中心度）ONA 协作网络中心度 top 8%（跨 3 个团队做节点）；360 里「出问题都找他」出现 6 次；但本人不爱发言 → 隐形核心。
③ 潜力（学习敏捷 / 跨级评价）半年自学会 Go 并迁移 2 个老服务；跨级评价写「可往上走」；主动接没人愿意碰的历史债。
④ 意愿（想去哪 / Internal mobility）想往技术架构方向；内部活水意向「否」（家庭原因短期不出京）；但薪酬已到带宽顶 → 留人隐患。
高潜关键人·勿动可继任（架构师后备）离职风险：中
②怎么采 · 四维数据从哪来
1
硬能力：拉项目系统 / 绩效系统里的实际战功，不是简历。问「他主导过什么难事、带过几个人、解决过什么反复出的问题」。
2
行为信号：ONA 取协作网络中心度；360 关键词提取（「都找他」「离了不行」）；经理提名 + 反向提名（「谁离开你最慌」）——专捞不爱说话的隐形核心。
3
潜力：学习敏捷（新技能掌握速度，如半年学会 Go）+ 挑战偏好（愿接没人碰的活）+ 跨级评价（上级的上级怎么看他）。
4
意愿：1:1 谈 + 内部活水系统意向。意愿变了（想走 / 想转）是前置风险信号，要标红。
5
动态更新：每季度刷新；关键事件（晋升 / 大项目 / 离职风险信号）即时更新，不静态存档。
③常见坑 · 反例
❌ 静态画像 = 只看职级学历：组织调整时按「职级高」优化，把隐形核心张三砍了 → 3 个团队瘫痪 2 周，才知道他多关键。
❌ 只采硬能力漏软信号：张三不爱发言，经理以为「存在感低」→ 没进高潜池，被竞对挖走。
❌ 不标意愿：张三薪酬到顶+想转架构，没人管 → 默默看机会，等递辞呈才慌。
面试能直接说：「画像不是把简历重抄一遍。我采四维交叉验证：硬能力看项目系统真实战功、行为信号用 ONA + 360 + 反向提名捞隐形核心、潜力看学习敏捷和跨级评价、意愿靠 1:1 和活水意向。关键是动态更新、标红风险——张三式的人（能力强但不爱说）最容易在静态画像里被漏掉。」

人才盘点（出决策）

用标尺量对象，盘完必有动作 · 九宫格 + 校准 + 风险 + IDP

① 完整示意示例 · 云技服某中心九宫格 + 校准结论

绩效 × 潜力；校准会消偏；标红「高宠高危」；盘完必出继任 / IDP / 风险

注：以下为「示意」落位，请代入你真实盘点
绩效\潜力低潜力中潜力高潜力
高绩效老王：稳定交付，可留任骨干小李：可重点培养，给挑战项目张三·高宠高危
标红：核心资产+易流失
中绩效老陈：守成，需激活或转岗小赵：有空间，补 __ 能力小孙：重点培养，列继任
低绩效待优化：PIP 或汰换新人期：给 3 月观察小周：绩效沟通+定位校准
关键岗位继任覆盖（没人能替＝红线）风控平台负责人：现可上 张三 / 1 年可上 小孙 / 还需培养 __。→ 张三若走，无即时备份＝红线。
风险清单（高宠高危 / 关键人流失预警）张三：薪酬到顶 + 想转架构 + 不出京 → 竞对可给架构岗。留人方案：带宽外特批 + 内部转架构通道。
发展计划 IDP（每人一条）张三：补「架构设计能见度」→ 3 个月内主导 1 次架构评审 + 带 1 个校招。owner：本人 + HRBP 双周跟。
校准会结论（消偏 / 捞埋没苗子）经理把小周（低绩效高潜）归错格 → 跨组对比发现同岗别人能带，定位为「放错项目」→ 调岗而非淘汰。
②校准会 runbook（怎么开才不黑箱）
会前
每人填好画像 + 初评，数据（绩效 / ONA / 敬业度）就绪；HRBP 先拉一份「疑似高宠高危」预警名单。
会中
逐人过：经理陈述（带证据）→ 其他人挑战证据 → 强制分布消偏 → 标定高宠高危。每人 8–10 min，一个中心半天开完。
消偏
四招：① 强制分布（避免全员优秀）② 跨组同岗对比（同岗拉一起评）③ 每条高潜必须有行为证据（说不出就降级）④ 反向提名捞埋没苗子（谁离开你最慌）。
谁参加
业务 leader + 上级 HRBP + 中心负责人 +（可选）跨中心 HR 当「外部眼」防近亲。
会后
出三张表：继任覆盖表 / 风险清单 / IDP 表，盘完必有动作，不盘完拉倒。
③常见坑 · 反例
❌ 收表出名单就完：经理自评全「优秀」→ 没有分布、没有校准 → 高潜名单无区分度，等于没盘。
❌ 黑箱定高潜：「我觉得他是高潜」拿不出证据 → 员工申诉公平危机，信任崩。
❌ 盘完无动作：出了九宫格锁进抽屉，张三的离职风险没人跟 → 三个月后真走，继任空白。
❌ 漏标高宠高危：只盯低绩效，忘了「高绩效高潜但想走」的人最贵也最易失。
面试能直接说：「盘点不是收表出名单，是出决策。我用绩效×潜力九宫格，但关键是校准会——强制分布消偏、每条高潜必须拿行为证据、反向提名捞埋没苗子，保证可解释。盘完必出三张表：继任覆盖（谁没人替是红线）、风险清单（高宠高危标红）、IDP。张三式的高绩效高潜但想走的人，是最贵也最该盯的。」
