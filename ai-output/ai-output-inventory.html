文化活动知识库AI自动化更新

内容/知识资产已沉淀
背景

文化活动资料散落在 KM、乐享、公众号、外部资讯，人工整理慢、易过期、来源难辨。需要一套能持续「采编—去重—沉淀」的自动化机制。

内容

由 knowledge-collection（知识采集）skill 驱动。主题池固定 6 个（员工大会 / Leader Offsite / 破冰 / 颁奖 / Open Day / 下午茶研讨），由 6h 轮询 automation 按序触发；自动多源搜索、判定一手/二手来源、做六维评估（相关度 / 权威性·一手加权 / 时效性 / 去重度 / 可落地质量 / 关系适配度，各 1-5 分、任一 <3 淘汰），与历史去重，沉淀为卡片墙 HTML 进 Obsidian「知识采集库」并关联 GitHub Pages。

细节

每张卡强制打「适用关系」标签——①平级/朋友 peer　②领导↔员工 supervisor　③领导↔领导 exec 三层，绝不混用；跨档内容关系适配度从严（平级向内容套到上下级直接判低分）。落库三端：Obsidian 知识采集库（汇总笔记+索引+本轮独立笔记）/ 乐享团队文件夹「待清洗素材」/ GitHub（SSH push master）。单文件 HTML、紫青 Bento、来源透明标注（📌云技服等）。

避坑

① 必须标一手/二手来源，别把二手当一手引用；② 与历史去重，避免同一案例反复沉淀；③ 外部资讯有时效，定时重跑而非一次性；④ 不硬写主办团队，用占位由人填；⑤ 案例仅做出处标注，不做主办断言；⑥「适用关系」标签必填，别把平级向团建游戏套到高管 Offsite（关系适配度从严）。

自动化系统已上线·月1触发
背景

新人发展答辩每月一次，建会、建群、看板回填、归档全是重复人工，易漏节点、跟催不及时。

细节

避坑

① 企微连接器断开会直接导致发不出（此前 wecom disconnected，需 webhook 或重连后才发）；② 月 1 触发确认时区/节假日，避免踩假期；③ 看板回填字段口径要对齐，防数据错位；④ 跟催设阈值而非天天催，别骚扰；⑤ 归档路径/权限先定好。

培训积分商城

推断稿·待核对
背景

【推断·待你核对】培训与文化活动（博闻多识·一堂课、AISee 实战沙龙、英语角、新人答辩等）参与靠自觉，活跃度波动、贡献难衡量，缺一个把「参与行为」变成「可积累权益」的激励闭环。

内容

【推断·待你核对】积分获取（参训 / 沙龙打卡、投稿分享、担任布道师等得积分）+ 积分商城（周边礼品 / 咖啡券 / 调休券 / 礼包等权益兑换）+ 参与看板 / 排行榜（活跃度可视化）。建议与抽奖平台、培训宣传文案 skill 联动复用。

细节

【推断·待你核对】需对接企业身份账号体系；积分规则防刷；参与看板可复用薪酬看板的数据可视化思路；兑换 SKU 与预算需提前对齐。

避坑

① 积分规则务必公开透明，避免争议；② 奖品预算与兑换履约要跟上，否则失信；③ 谁多少分属敏感数据，权限与脱敏要管；④ 别和薪酬 / 奖金报销混淆（激励 ≠ 薪酬）；⑤ 防刷分（代打卡 / 刷分识别）。

抽奖平台

产品/平台已上线·Railway+Pages
背景

文化活动（年会 / 表彰 / 团建 / 节日）抽奖高频，现成工具要么收费、要么规则不灵活、要么不支持名单管理。自建更可控。

内容

Web 应用：Vue3+Vite 前端 + Express+SQLite 后端，抽奖逻辑、概率权重、中奖名单管理、多人并发抽奖；Railway 部署后端 + GitHub Pages 托管前端。

细节

技术栈 Vue3+Vite / Express+SQLite；后端 Railway、前端 Pages；支持名单导入 / 去重、概率配置。

避坑

① 并发抽奖必须防超发/重复中奖（事务或锁）；② 概率权重配置要对，别算错；③ Pages 只托管静态，后端必须另部署（Railway）别混；④ 名单去重 + 防刷；⑤ 中奖名单涉隐私，权限与脱敏要管。

自建 skill 体系

AI 能力资产持续迭代·16文件/11顶层
背景

活动 SOP、主持稿、谈参、培训宣传、知识采集、抖音生产、报告防错等场景反复出现，每次重写 prompt 低效且质量不稳，沉淀为可复用 skill 才是资产。

内容

实际自建（agent_created: true）共 15 个文件 = 10 个顶层 skill；抖音生产体系含 6 个自建子层。每个解决一类反复出现的重复痛点：

  • culture-event-sop（文化活动 SOP）→ 员工大会/Offsite/团建/Openday 每次都得从零想方案、找模板、列 checklist，重复且质量不稳。
  • exec-talk-prep（高管谈参/致辞）→ 高管每次出场临时写发言稿，易漏保密提醒、职位确认等坑。
  • host-talk-prep（主持稿通用版）→ exec-talk-prep 太私有化同事复用不了，抽成通用方法论供内部复用。
  • training-promo-copy（培训宣传文案）→ 每次培训/活动手写招募推文、群公告、海报文案，风格不一、费时。
  • knowledge-collection（知识采集）→ 文化素材靠人工网上搜，慢、易重复沉淀、一手/二手来源不清。
  • campaign-recap（营销活动复盘）→ 每次活动复盘口径不一、手动算 ROI/五维评分慢且易错。
  • talent-intel-mapper（人才情报地图）→ 竞品/组织盘点时人工搜公开信息零散、置信度不清。
  • tencent-meeting-minutes（会议全流程自动化）→ 会后纪要靠手工整理、参会人核对繁琐，建会改会也重复。
  • ui-design-spec（UI 设计规范）→ 每次展示/活动类 HTML 风格不统一，反复调审美。
  • xhs-hr-content（小红书 HR 内容方法论）→ HR 博主内容选题靠拍脑袋、钩子弱打开率低、发前无打分、改稿凭感觉，风格与质量难稳定。
  • douyin-pro 体系（抖音生产，含 6 自建子层：大脑/脚本优化/混剪/绘图/渲染/采集）→ 短视频链路长，每步人工重复、风格难统一、合规易踩雷。

⚠️ 此前盘点把 data-report-guard 也算进自建，实测它未标 agent_created（属安装所得），已剔除。

细节

存于 ~/.workbuddy/skills/，共 16 个 agent_created 文件（11 顶层 + 抖音 6 子层）；触发词需收窄避免误触发；部分依赖外部 MCP（ima/lexiang）尚未连接；有 skill 自查/审计机制。

避坑

① 触发词过宽会误触发并撑爆上下文（抖音 skill 卡顿根因）；② 主 SKILL 过大要精简、收窄触发词；③ 子层引用缺失（brain-layer.md / run_autoclip.py 等）要清理；④ 别重复造相似 skill，先查已有；⑤ 改完要实测验证闭环。

细节

培训效果与原声反馈看板

已上线·数据看板
背景

博闻多识·一堂课、AISee 实战沙龙等培训持续运营，但效果过去只靠"开了几场"衡量，缺人均深度、真实感受与学员原声，难证明价值、也难迭代。

内容

数据看板（bowen_dashboard）：效果维度＝去重人数 / 参与人次 / 人均参与深度 / 参与时长（<15min 剔除、空白排除）；感受维度＝学员原声反馈、满意度。脚本 dashboard.py / build_dashboard2.py 产出 HTML 看板。

细节

区分去重人数 vs 参与人次，避免重复计数虚高；人均参与深度为核心指标；参与时长清洗（<15min 与空白剔除）保证质量；效果×感受双维度并跑、已维护半年。

避坑

① 去重人数与参与人次必须分清，别用人次冒充覆盖；② 参与时长设阈值剔除刷场/挂机，空白排除；③ 原声反馈要脱敏、去标识；④ 指标口径锁死写进脚本，别每次手算；⑤ 数据来源优先复用学员明细，别手抄清单。

leaderAI教练（管理教练对话 prompt）

AI 能力资产对话prompt·非skill
背景

leader 要跟下属做绩效改进 1-on-1，但不知怎么开场不打击人、怎么探查卡点、怎么定支持动作；直接问通用 AI 又常得到「你要更努力」式空话。需要一个结构化的管理教练对话框架。

内容

一个精心设计的「管理教练」对话 prompt（原文已存档 Obsidian 素材库/leaderAI教练-prompt.md）：输入下属背景（入职时长 / 表现前后变化 / 观察 / 目标），固定输出四段——① 开场白（≤3 句、低压迫、可念）② 3 个探查性问题（帮自查、不质问）③ 卡点假设（技能 gap / 资源不足 / 动机）+ 每种对应支持动作 ④ 结尾对齐（1 个本周微小改进 + 下次跟进时间）。

细节

形态＝对话 prompt（直接喂通用模型，非持久 skill；已查证 ~/.workbuddy/skills/ 无此 skill）；四段式结构固定、可复用于任意绩效/辅导 1-on-1；核心约束＝口语化、不替 leader 下绩效结论、信息不足标（需确认）、禁止「你要更努力」类空话、只基于给定信息不编造。

避坑

① 不替 leader 下绩效结论（绩效改进场景越权/法律风险高，AI 只做教练不做裁判）；② 信息不足必须标（需确认）而非编造下属情况；③ 开场低压迫，避免打击信心；④ 禁止空话（「你要更努力」等无行动指引的话）；⑤ 只基于给定信息，不脑补下属表现。
